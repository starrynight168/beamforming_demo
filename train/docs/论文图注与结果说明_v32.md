## 统一写作口径

- H32×OC8、H64×OC8 或其他候选都只能按实际 checkpoint 命名，不能把 YAML 默认值写成最终主线；
- 活体报告逐帧 SSIM 的 mean/SD/CI 和 paired difference；
- 四个受控 scene 分别报告，不跨 scene 合并均值；contrast 用 CR/CNR/gCNR，resolution 用 lateral/axial FWHM/PSLR；
- PTQ、common MC、HWA-QAT 分组报告；common 是行为级压力，不是器件 worst-case；
- software runtime 不写成 chip latency/area/energy；logical coefficient/device/tile/area 分开。

## 尺度与部署口径

本次软件验证只支持：在测试条件下，FP32 路径的 E/explicit 与 F/factorized 数值一致。两条路径使用同一套网络输入归一化和预测权重；不能据此写成所有数值条件下严格不变。固定 `ε`、低位宽舍入、前端噪声、饱和和其他非理想都会破坏等价性。

部署流程分为两条数据路径：预测权重时，原始对齐 IQ 经过 RMS 或 std 归一化后输入网络；波束合成时，原始对齐 IQ 直接与预测权重相乘并求和。RMS 与 std 的成本差异只在网络输入预处理端；若 std 包含减均值，则该端增加均值计算和减法。波束合成端只执行原始 IQ 与权重的乘加。

RMS 只控制平均幅度，不能保证每个样本的峰值处于 ADC/DAC 线性范围，也不能恢复前端截断信号。TGC 是随时间变化的增益，不能整体等同于单个全帧标量。

“忆阻器直接做动态波束合成”仍是待验证的硬件任务。FC 阵列保存固定网络参数，而预测的孔径权重随像素变化；逐像素写入电导，或通过电压输入动态权重，都需要额外的更新、乘法、累加和外围电路。当前软件中的加权求和和 F/factorized 路径不能证明该硬件已实现。

直接使用原始对齐 IQ 不等于已证明节能、面积或延迟收益；这些收益必须由硬件实现数据评估。

当前部署描述：

> 数字前端完成对齐，RMS 或 std 归一化只用于网络输入；忆阻器网络预测控制点，随后生成孔径权重并直接加权原始对齐 IQ。实际硬件收益尚待评估。

打包尺度统一称为“全帧复数 RMS 尺度”：当前 `pack_EPFL.py` 和 H5 元数据使用 `sqrt(mean(I² + Q²) + ε)`，保存为 `all_scale_ref`。波束输出经 TGC 后的峰值保存为 `safe_max_*`，显示归一化参考保存为 `norm_ref_*`，不能与输入 RMS 尺度混称。

## 正文图序

### Fig. 1 方法和系统边界

```text
aligned IQ → candidate network → K controls → K→M interpolation → physical weights → complex beamforming
```

标出公共 RF/TOF/RMS 与 envelope/TGC/log 链路，以及 CIM core、数字插值和波束形成边界。

### Fig. 2 控制空间机制

展示候选网络、K 个控制量、动态孔径 M(z)、插值后的权重曲线和代表性像素。说明 K 是学习自由度，M 是物理求和通道；不要把 K 减少写成物理通道消失。
若加入 DAS/MV 基线，将其作为无学习控制点的 M-channel physical baselines 放在物理权重面板，不计入 K。控制量面板必须按各模型真实原生输出槽位绘制，保留不同 K 的尺寸差异以及动态孔径外的零值；不能用统一归一化横轴掩盖模型大小。物理权重统一使用 unity-normalized effective weights，并标明实际 M 与当前像素的 M(z)。

### Fig. 3 活体定性结果

固定 10 个 test frames、ROI、空间范围和 display range，比较 reference、FP32、PTQ4 `linf`/common 和 HWA-QAT4/common 等实际存在的候选。不得单独调每种方法的显示范围；split 中 50 个 test 条目不能写成当前主线已报告 50 帧。

### Fig. 4 活体定量结果

展示逐帧 SSIM、paired Δ、envelope SSIM 和 CI。SSIM 只表示相对 reference 的保真度，不替代临床或物理成像质量。

### Fig. 5 受控物理场景

按 simulation/experiment 与 contrast/resolution 分开，报告 CR/CNR/gCNR 和 FWHM/PSLR。不同 scene 和不同物理指标不压成一个总分。

### Fig. 6 低维质量—资源折中

比较 Direct-Full、post-hoc projection 和 native K-control；横轴可用 K、logical coefficients、physical devices、tile/PPA。factorized 只写成不物化 M 维权重，不能自动写成减少物理 IQ 通道或 MAC。

### Fig. 7 低比特工作点

展示 FP32 与 PTQ8/PTQ6/PTQ4/PTQ3 的 `none`、`linf` ladder，并明确 4-bit weight 是 differential G+/G− per-device conductance precision。PTQ4 进入后续 common 压力前，必须完成 train-only calibration；当前 ladder 结果只作工作点诊断，不宣称 PTQ4 无损。

### Fig. 8 common 硬件压力

展示 PTQ4 `none`/`linf` 下的 IR-drop、ADC、drift、stuck-at、write/read 和 TIA 单因素，以及 QAT4 common 组合 MC30。只报告 YAML 实际启用的非理想项；未启用字段放在限制中。

### Fig. 9 HWA-QAT 恢复

统一 checkpoint 语义版本和配置后，比较相同候选、相同 common profile 和相同 realization 下的 PTQ4 与 HWA-QAT；报告 recovery gap、remaining gap、mean/SD/P5/P95/CI。现有图的 recovery 数值在一致性审计完成前只作诊断。

### Fig. 10 mapping 与 PPA 边界

展示定制紧凑 mapping、G+/G− devices、converter dimension/count、CIM core、standard peripherals、custom add-on 和 full-flow ledger。NeuroSim/CrossSim 不代表完整芯片。
