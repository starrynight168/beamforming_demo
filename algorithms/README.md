# 算法介绍与实现说明

界面和命令保持 DAS、MV、CCMV、ESBMV、GCF-MV、CMSAW、F-DMAS、MBAN 的原名称。

| 名称 | 介绍 |
| --- | --- |
| DAS | 将各通道信号按传播时间对齐，按接收孔径权重相加，再相干复合选定角度。 |
| MV | 根据局部协方差自适应求解接收权重，在保持目标方向增益的约束下抑制干扰。 |
| CCMV | 对重叠子阵先求均值，再以均值的外积估计包含全部配对的交叉矩阵，求解自适应权重。 |
| ESBMV | 将 MV 权重投影到信号子空间，以减弱噪声与干扰分量。 |
| GCF-MV | 将相干性权重与 MV 合成结合；当前单角度使用接收孔径流程，多角度使用二维联合流程。 |
| CMSAW | 以修改协方差矩阵的均值与标准差之比计算像素权重，并作用于 MV 输出。 |
| F-DMAS | 对延时对齐的不同通道信号进行成对乘积并合成，利用通道间相干性抑制杂波。 |
| MBAN | 加载训练检查点，使用模型生成接收控制量并完成重建。 |

## CMSAW 与 F-DMAS 的数据定义

现有 H5 输入是经过解调的复数 IQ。

F-DMAS 入口当前采用保留相位的幅度开方与复数成对乘积，并按有效通道对权重归一化。其 IQ 公式可参考 [van de Schaft 等，2025，式 (17)](https://doi.org/10.1109/TUFFC.2025.3586377)。[Matrone 等，2015](https://pubmed.ncbi.nlm.nih.gov/25420256/) 的原始 RF 方法包含实数有符号开方和带通滤波；当前代码不能直接视作该 RF 流程的逐式复现。

CMSAW 当前逐角度在接收通道 IQ 上计算权重，采用包络标准差与复数矩阵统计，再合并权重并作用于 MV 输出。[Wang 等，2022](https://link.springer.com/article/10.1186/s12938-022-01007-5) 使用接收合成数据的处理流程，因此二者的数据组织不同。默认直接保留 MSR；`gamma=1`、`clip_percentile=100`、`depth_smooth_rows=1` 分别关闭额外幂次、裁剪和平滑。

这些说明仅用于交代方法定义，不构成画质优劣结论。

## CCMV 的当前定义

以 `x_i(t)` 表示第 i 个重叠子阵，当前估计式为：

`xbar(t) = sum_i b_i x_i(t) / sum_i b_i`

`Rcc = sum_t xbar(t) xbar(t)^H / T`

已依据用户提供的 [Hasegawa 与 Nagaoka，2020](https://doi.org/10.1007/s10396-020-01009-7) 全文第 205 页核实：式 (9) 的双重求和包含 `i=j`，分母为 `N^2`，没有排除自身配对。矩形窗、`temporal_win=1`、`fbss=False` 时，当前矩阵估计与原文 `Delta_n=1`（不抽取子阵）严格等价。时间平均、FBSS 和非矩形加权为现有接口扩展。原先排除自配对的估计不符合式 (9)，可能产生不定矩阵及异常峰值。

按用户最终要求，CCMV 直接继承现有 MV 的构造器、动态孔径、重叠子阵、加载、权重求解和输出，只替换协方差估计。CLI 解析器复制 MV，仅单独设置 CCMV 的加载默认值；MV 保留原加载设置（根配置和 CLI 为 `0`，直接构造器默认 `0.01`），CCMV 加载为 `0.1`；根配置两者均为 `subarray_ratio=0.25`、`temporal_win=9`、`fbss=True`，共用动态孔径、F-number、窗函数、插值与显示参数。子阵步长沿用 MV 的 1，对应式 (9) 的 `Delta_n=1`。

原文式 (10) 的 `Delta=0.1/L` 对应代码 `mv_dl=0.1`，原文实验的接收孔径和子阵分别为 72 与 24 阵元；这些实验参数未用于当前配置。此前试验添加的固定孔径参数已撤回；MV 代码已完全恢复原样，CCMV 单独覆盖加载默认值。公共求解器的机器精度稳定项保留。当前除加载单独设置外，孔径、子阵及平滑参数均复用 MV，并非复刻原文采集条件。

## MBAN 配置加载

默认优先使用检查点旁的 `effective_config.json`，保持该模型的配置快照，避免当前训练配置新增其他模型字段后影响已有模型推理。若检查点位于完整的 `train` 目录下，可自动找到训练包；否则用 `--train_root` 指定。

`--config` 可显式指定配置。JSON 快照恢复保存的硬件 profile；若要替换外部硬件 YAML，需显式指定 YAML `--config` 和 `--eval-config`。原始训练配置不会为运行已有检查点而删除字段。
